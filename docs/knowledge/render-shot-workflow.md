# render-shot-workflow

> How to capture matched before/after stills, preview sibling branches together and smoke-test the real UI for gods-and-titans render work (software GL timing, flags, traps)

For any graphics thread ([graphics-overhaul-plan](graphics-overhaul-plan.md), [gods-titans-graphics](gods-titans-graphics.md)):

- Stills: `node tools/shot-terrain.mjs --quality medium --scenes lake,shore,far,rocks,rockup,hills,base,dock --width 1280 --height 720 --clean --out DIR --prefix NAME [--tod golden|day|dusk|night|dawn|<hour>] [--eval 'h.renderer...'] [--timeout 900000]`. It drives `tools/render-harness.html` (manual clock, `reveal=1`) and finds the lake, shore, open rock cluster and highest meadow itself, so every run frames the same map. `--tod` works on main since Lighting (#20) merged; older checkouts ignore it.
- Software GL (swiftshader) costs: medium 3 to 5 s a frame, high and ultra 10 to 12 s at 1280x720, first load about 15 s. The machine has 4 cores: run one capture job at a time, background it and wait for the notification.
- Before shots: `git worktree add --detach <dir> <sha>`, symlink `node_modules`, shoot with `--prefix before`. The tool is on main since #22; for an older sha copy it in, and delete that stray copy before checking out a newer sha (the checkout aborts on the untracked file). To check a merge itself, detach a worktree at the squash sha and shoot `--tod golden`, `day` and `night` (done for 99f83e8: clean).
- Preview a sibling branch's look together with yours: a scratch worktree on a throwaway branch (`git worktree add -b tmp-merged <dir> <my branch>`, then `git merge origin/<sibling branch>`); never push it.
- Real-UI smoke test: `node tools/play-test.mjs --only sp --out DIR` (27 checks, a few minutes). On the 4-core sandbox its 30 s screenshot timeout trips even on main: raise it to 240000 locally with `sed` in `shot()` (never commit) and add `--size 960x540`; then 27 pass.
- Tests: `npm test` (`node --test "tests/**/*.test.js"`, about 60 s); ad-hoc node scripts need the `register` resolver hook from the tests to find `three` under `vendor/three`. `npm run e2e` points at a folder that does not exist.
- Camera `setDistance` clamps at 10 (not a bug). Share stills by copying them into (an off-repo folder, not kept) and attaching them to the reply; a thread allows only 24 attached files in all (the character-look thread hit it at part 4), after that link each still by its path in the reply text.
- Characters: `node tools/shot-characters.mjs --detail base|rich --scenes mortals@13,gods@15,field@25,army@20,unit:norse_thor@6~0.4 --tods golden,dusk,night --canvas --clean --t 8 --width 1280 --height 720 --out DIR --prefix NAME` (the pantheon scenario, real renderer; `--t 8` skips the gods' golden summon pillars; `--eval` runs code on `h` before the shots, e.g. to select units or set `e.rank`/`e.xp`). One job at a time: a rich High capture is about 20 to 40 s a still. Film strips: `tools/gallery-units.html?detail=rich&filter=norse&looks=1&real=1&state=attack&film=0,0.1,0.2,0.3&focus=warrior&zoom=1.5`. Never `pkill -f run.sh` from a shell whose own command line contains that text (it kills the shell).
